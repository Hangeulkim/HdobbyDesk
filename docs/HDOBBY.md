# HdobbyDesk

> 이 문서는 개발 중 누적된 검증 기록입니다. 현재 배포 상태와 사용자 연결 절차는 [README](../README.md)를 먼저 확인하세요. 이전 버전의 시험 결과를 최신 버전 전체의 성공으로 해석하지 마세요.

## 현재 상태

RustDesk 1.4.9의 소스를 기반으로 만든 직접 연결·입력·UI 개선 작업입니다. 2026-09-15 현재 Windows 호스트에 Android와 Mac 컨트롤러가 실제로 직접 연결되는 경로는 확인했지만, 모든 플랫폼 방향과 장시간 안정성을 검증한 공용 릴리스로 취급하지 마세요.

직접 연결 우선, 공개 ID·중계 서버 미사용, 사용자가 지정한 내부 중계 선택을 기준으로 수정했습니다. 공개 ID·API·STUN·업데이트 기본값과 중계 자동 선택을 제거하고 인증서 지문을 확인하는 TLS 1.3 직접 연결을 추가했습니다. Mac ARM64 코어·서비스·Flutter UI, Android ARM64 APK, Windows x64 코어를 빌드했습니다. Windows 설치 서비스에는 최종 코어를 배포해 연속 재시작과 외부 직접 포트 접근을 확인했고, 실물 Android에서는 이동통신망으로 Windows 화면과 터치 입력을 확인했습니다. Mac v35는 저장된 인증서·영구 비밀번호·Console 세션으로 완전 재시작 후 자동 연결됐고, v34의 30분 연속 연결도 단절 없이 끝났습니다. 운영 설정은 Git 밖에 두고 기본 테스트는 로컬에서 실행합니다. [네트워크 변경](PRIVATE_NETWORK.md)과 [시험·서버 정보 관리](PRIVATE_TESTING.md)를 따르세요.

## 선정과 플랫폼 범위

사용자는 MIT를 우선하되 적절한 후보가 없으면 GPL 계열을 허용했습니다. RustDesk는 이번 요구의 플랫폼 범위와 기존 입력·연결 구현을 재사용할 수 있는 후보입니다. 공개 기능 지원은 이 수정본의 실기기 검증 결과를 의미하지 않습니다.

| 플랫폼 | 원격 기기 조작 | 호스트 | 이번 수정본 실기기 검증 |
|---|---|---|---|
| Windows | 지원 | 지원 | Android→Windows 직접 연결·입력·RDP 공존 확인; Windows→Mac 최종 확인 미완료 |
| macOS | 지원 | 화면 기록·손쉬운 사용 등 권한 필요 | Mac→Windows 직접 연결·Console 화면·자동 재인증 확인; 실제 입력·IME 전체 절차 미완료 |
| Android | 지원 | 화면 캡처·입력 제어 권한과 기기 제약 확인 필요 | Windows 컨트롤러 경로 확인; Android 호스트 전체 절차 미완료 |
| iPhone | 지원 | 이번 요구에서 제외 | 텍스트·PNG 컨트롤러 경로 구현; 전체 Xcode 빌드와 기기 시험 미검증·커밋 전 필수 시험 제외 |

공식 근거: [클라이언트 문서](https://rustdesk.com/docs/en/client/), [Android 문서](https://rustdesk.com/docs/en/client/android/), [모바일 지원 안내](https://rustdesk.com/blog/rustdesk-remote-control-android-ios/).

MIT 후보 Deskhub는 [공식 저장소](https://github.com/manhpham90vn/Deskhub)에서 모바일 호스트가 화면 보기 범위인 점과 모바일 베타 상태를 확인했고, [BilldDesk 공개 소스](https://github.com/galaxy-s10/billd-desk)의 기능표는 Android 호스트를 Pro와 구분하므로 이번 기반으로 선택하지 않았습니다. 어떤 후보도 이 환경에서 장시간 연결 안정성 비교 측정을 완료한 것은 아닙니다.

## 추가한 UI

데스크톱 원격 툴바와 모바일 하단 바에 입력 도우미를 추가했습니다. 모바일 바는 좁은 화면에서 가로로 스크롤할 수 있습니다.

- Windows 원격 한/영 버튼: 한국어 IME에 `VK_HANGUL`을 보냅니다. 한국어 IME가 먼저 선택되어 있어야 합니다.
- Mac 원격 입력 전환 버튼: `Control+Space`를 보냅니다. 원격 Mac에 한국어·영어 입력 소스와 해당 단축키가 설정되어 있어야 합니다. 입력 소스가 여러 개라면 반드시 한/영만 오가는 것은 아닙니다.
- 전환 버튼은 기존 Map 모드를 선택합니다. 물리 키 위치가 원격 키보드 배열을 따르게 하려는 목적이며, 다른 배열을 사용했다면 동작 변화가 있으므로 UI에 안내합니다.
- 한글·줄바꿈·이모지를 로컬 편집창에서 완성하고 명시적으로 한 번 전송할 수 있습니다. 입력 중 변경값은 자동 전송하지 않습니다. 원격 앱의 실제 수신 확인 기능은 없으므로 성공 표시도 ‘전송 요청’으로 표현합니다.
- 좌/우/더블 클릭, 방향키, Enter/Backspace/Tab/Esc, 원격 OS에 맞는 Ctrl 또는 Cmd 단축키를 제공합니다. 새 모바일 설치는 화면에서 누른 위치를 직접 지정하는 터치 모드를 기본값으로 사용합니다. 선택 가능한 트랙패드 모드는 호스트의 단일 시스템 커서를 공유하므로 로컬 사용자가 동시에 마우스를 움직이면 다음 클릭 위치가 달라질 수 있습니다. Android 호스트에서는 데스크톱용 클릭·클립보드 단축키를 숨깁니다.
- 전송 중 중복 요청을 막고, 오류 시 초안을 보존하며, 제어 권한이 없으면 전송을 막습니다. 화면을 닫을 때 키보드 표시 상태를 정리합니다.

코드: [입력 UI 패키지](../flutter/packages/hdobby_input/lib/hdobby_input.dart), [RustDesk 연결 어댑터](../flutter/lib/hdobby/input_helper.dart).

## 다중 접속 입력

선택형 협업 커서는 접속마다 이름·색·절대 위치를 따로 유지합니다. 포인터를 움직이는 동안에는 Windows의 단일 시스템 커서를 건드리지 않고, 클릭할 때만 해당 접속자의 마지막 위치로 이동해 버튼 입력과 한 잠금 안에서 처리합니다. 드래그 중에는 그 접속자가 최대 10초 동안 시스템 커서를 소유하며 연결 종료·시간 초과 때 눌린 버튼을 해제합니다. 일반 응용프로그램의 실제 포커스와 시스템 커서는 하나이므로 서로 다른 두 창을 동시에 드래그하는 기능은 제공하지 않습니다.

Windows 호스트에서는 각 접속자의 물리 키보드를 별도 Xbox 360 호환 가상 패드로 변환하는 선택 기능을 추가했습니다. XInput 한계에 따라 최대 네 접속이며, 모든 슬롯이 찼을 때는 새 접속에 기능을 사용 가능하다고 표시하지 않습니다. 켜진 접속의 키 입력은 데스크톱으로 새지 않고, 기능 해제·접속 종료 때 중립 상태를 보낸 뒤 그 접속의 패드를 제거합니다. 현재 백엔드는 MIT 라이선스 ViGEmClient와 별도로 설치된 서명된 ViGEmBus를 사용하며 드라이버를 자동 다운로드하거나 설치하지 않습니다. 이 드라이버는 유지보수가 종료됐으므로 호환 기능으로만 취급하고 실제 네 명 동시 입력은 아직 검증하지 않았습니다.

동작·키 배치·제약은 [협업 입력 문서](COLLABORATIVE_INPUT.md)에 구분했습니다.

## 호스트 관리 화면 가림

Windows 10 2004 이상에서는 HdobbyDesk의 메인 관리 창, 연결 관리자와 설치 창에 `WDA_EXCLUDEFROMCAPTURE`를 적용합니다. 로컬 사용자는 창을 계속 보고 조작할 수 있지만 지원되는 Windows 캡처 API가 만드는 원격 영상에서는 제외됩니다. 원격 데스크톱 뷰어 창은 제목 정책에 포함하지 않습니다. Windows v42 교차 빌드는 통과했지만 실제 Windows 호스트에서 로컬 표시와 원격 영상의 차이는 아직 확인하지 못했습니다. 이 기능은 다른 관리자 프로그램이나 UAC 화면을 자동으로 가리지 않으며 보안 경계를 대신하지 않습니다. 자세한 범위는 [관리 화면 가림 문서](ADMIN_PRIVACY.md)에 있습니다.

## 한/영 전환에서 확인해야 할 점

UI 버튼 추가는 비교적 작게 구현할 수 있습니다. 맥에서 바꾼 언어를 Windows에 자동으로 동기화하려면 로컬 입력 소스 변경 관찰, 원격 포커스 앱의 실제 IME 상태 조회·설정, 세션별 상태 응답, 재연결과 키 반복 처리까지 필요합니다. 단순히 양쪽에 토글을 보내면 시작 상태가 다르거나 한 번 누락됐을 때 반대로 어긋날 수 있습니다. 이 작업은 자동 상태 동기화를 아직 구현하지 않았습니다.

[RustDesk FAQ](https://github.com/rustdesk/rustdesk/wiki/FAQ#keyboard-translation-modes)는 Map 모드와 Translate 모드를 구분합니다. Translate 모드의 로컬 문자 전달과 원격 IME를 사용하는 물리 키 전달을 혼동하면 표시 상태와 실제 입력이 다를 수 있습니다. 이번 모드 선택이 모든 IME 문제를 해결한다는 실측 증거는 아직 없습니다.

[공개 이슈 #14498](https://github.com/rustdesk/rustdesk/issues/14498)는 Windows 11→Windows 11, 1.4.6에서 전환 표시가 바뀌어도 영문이 계속 입력된다고 보고합니다. 이것을 Mac↔Windows 또는 1.4.9에서 재현된 것으로 해석하지 않습니다.

키 근거: [Microsoft VK_HANGUL](https://learn.microsoft.com/ko-kr/windows/win32/inputdev/virtual-key-codes), [Apple 입력 소스 전환](https://support.apple.com/ko-kr/guide/mac-help/mchlp1406/mac). 로컬 구현에서도 `src/client.rs`, `src/server/input_service.rs`, `libs/enigo/src/win/win_impl.rs`의 Hangul 키 경로를 확인했습니다.

## 검증 결과와 재현

독립 UI 패키지는 Flutter 3.24.5 / Dart 3.5.4로 테스트했습니다. 2026-09-15 현재 직접 연결 코드·인증서 등록·입력 도우미·재연결·Windows Console/RDP 선택·화면 크기 관련 53개 테스트가 통과했습니다. 상위 앱의 입력 수정키·최근 연결 병합·브랜드·설정·iOS 클립보드 관련 24개 테스트도 통과했습니다. 이 테스트는 네이티브 Rust 브리지나 네트워크를 실행하지 않습니다.

새 연결 어댑터의 Dart 분석은 문제 없음으로 끝났고, 수정한 데스크톱·모바일 툴바 분석은 오류 없이 기존 API 폐기 예정 안내 28건을 반환했습니다. 이 역시 네이티브 앱 전체 빌드 결과가 아닙니다.

```sh
cd flutter/packages/hdobby_input
flutter pub get
flutter test
flutter analyze
```

실제 Flutter UI를 브라우저에서 확인할 수 있는 독립 테스트 화면도 포함했습니다. 이 화면의 입력은 로컬 테스트 기록으로만 전달됩니다. 원격 연결 기능이 있는 웹 클라이언트가 아닙니다.

```sh
cd flutter/packages/hdobby_input/example
flutter pub get
flutter run -d chrome --web-renderer html
```

브라우저에서 한국어 UI 표시와 한글·줄바꿈·이모지 입력, 명시적 전송 후 초안 비우기, 실패 안내와 초안 보존을 확인했습니다.

이후 Rust 1.81.0, cargo-expand 1.0.95, flutter_rust_bridge_codegen 1.80.1을 작업 폴더에 준비해 실제 브리지를 생성했습니다. Flutter SDK에는 원본 워크플로의 `flutter_3.24.4_dropdown_menu_enableFilter.diff`를 적용했습니다. macOS 표준 헤더 검색 오류는 Command Line Tools의 SDK 경로를 명시해 해결하고, 오류가 사라진 생성 로그를 확인했습니다. 새 UI를 포함하는 실제 앱의 전체 Flutter 코드는 Mac ARM64의 `App.framework`로 컴파일됐습니다.

```sh
# 저장소 루트, 위 버전의 도구와 의존성 준비 후 실행한 Mac 전용 명령
RUST_LOG=info flutter_rust_bridge_codegen \
  --rust-input ./src/flutter_ffi.rs \
  --dart-output ./flutter/lib/generated_bridge.dart \
  --c-output ./flutter/macos/Runner/bridge_generated.h \
  --llvm-path /Library/Developer/CommandLineTools/usr \
  --llvm-compiler-opts='-isysroot /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk'
cd flutter
flutter assemble --output=build/hdobby-macos \
  -dTargetPlatform=darwin -dBuildMode=release -dDarwinArchs=arm64 \
  -dTargetFile=lib/main.dart -dTreeShakeIcons=false \
  release_macos_bundle_flutter_assets
```

공식 1.4.9 Mac 앱의 검증된 Runner와 플러그인 프레임워크에 현재 소스에서 만든 Flutter App.framework, Rust 코어와 서비스를 넣은 v35 개발용 앱을 만들었습니다. 공식 앱과 로컬 SDK의 Flutter 엔진 식별자는 `a18df97ca57a249df5d8d68cd0820600223ce262`로 일치했습니다. v35는 Windows 호스트의 저장된 인증서·영구 비밀번호·Console 세션을 사용해 완전 종료 뒤 추가 입력 없이 다시 연결됐고 실제 Console 잠금 화면을 표시했습니다. 연결 창 제목은 저장된 기기 이름만 표시해 직접 주소가 화면 캡처에 남지 않게 했습니다. Space 키, 영문·숫자 문자 입력·삭제와 마우스 클릭은 실제 Console에서 확인했습니다. v34로 같은 Console에 연결한 30분 관찰에서도 프로세스와 단일 TCP 연결이 전 구간 유지됐습니다. 로그인 이후의 한·영 IME 조합 입력과 원격 툴바의 모든 기능은 아직 전체 검증하지 않았습니다.

최신 Mac v42는 협업 커서·접속별 키보드 게임패드 UI와 iOS 클립보드 공용 브리지를 포함한 Flutter App.framework, ARM64 Rust 코어와 서비스를 다시 조립했습니다. 로컬 ad-hoc 서명, 전체 번들 서명, 외부 라이브러리·비이식 경로·그룹/전체 쓰기 권한, 공개 서비스 주소와 운영 인증정보 검사를 통과했습니다. 공용 배포용 Apple 서명·공증과 v42 실기기 재연결은 미완료입니다.

기본 화면에서 자동화 도구로 보낸 `Cmd+A` 뒤 Backspace가 전체 문자열을 지우지 않은 사례가 있었습니다. 동일한 시험을 수정하지 않은 공식 앱에서 수행해 같은 현상을 확인했습니다. 따라서 수정본에서 새로 생긴 결함으로 판정하지 않습니다. 자동화 입력 경로와 원본 앱 동작 중 원인은 미확정이며 단축키 성공으로 기록하지 않습니다. 시험 문자열은 필드 값 설정으로 비웠고, 최종적으로 개발용 앱과 공식 시험 앱 모두 실행 중이 아님을 확인했습니다.

이 Mac에는 전체 Xcode가 없지만 macOS Rust 코어·서비스와 Flutter App.framework는 현재 소스에서 빌드했습니다. 검증된 Runner·플러그인 프레임워크와 조립한 로컬 앱은 ad-hoc 서명과 전체 서명 검증을 통과했습니다. Runner·플러그인을 다시 빌드한 공용 배포본과 Apple 공증은 미완료입니다. Android ARM64 코어·서명한 APK와 Windows x64 코어도 빌드했으며, Windows 서비스의 두 차례 연속 재시작 뒤 직접 수신 상태와 Mac에서의 연결을 확인했습니다. 최신 Windows v42 코어에는 물리 Console 기본값, 협업 커서, 접속별 키보드→XInput 게임패드와 관리 창 캡처 제외를 포함해 교차 빌드와 패키지 무결성 검사를 통과했지만 기존 Windows 설치본에는 아직 배포하지 않았습니다. iOS 수정본 빌드·서명과 실기기 시험은 미완료입니다. 기존 [브리지 워크플로](../.github/workflows/bridge.yml)와 [전체 빌드 워크플로](../.github/workflows/flutter-build.yml)가 전체 배포 절차의 기준입니다.

Android ARM64용 Flutter UI·Rust 코어·플러그인을 빌드하고 APK를 패키징했습니다. 실물 Android의 2092 빌드에서 저장된 인증서와 영구 비밀번호를 재사용해 이동통신망으로 Windows 호스트에 직접 연결했습니다. Windows 세션 선택, 실제 바탕 화면 표시, 자동 가로 전환, RDP 동시 유지와 터치 입력을 확인했습니다. 앱 강제 종료 뒤 최근 연결을 한 번 눌러 다시 연결했으며 인증서나 비밀번호를 다시 묻지 않았습니다. 2093은 새 모바일 설치의 기본값을 터치 모드로 바꿨습니다. 2094는 Android 14 이상에서 전체 화면 공유를 기본으로 선택하고, 승인 직후 가상 화면을 만든 뒤 연결마다 재사용하도록 바꿨습니다. API 36 가상 기기에서 지연 연결·강제 종료·재연결 동안 승인창 재등장 없이 캡처가 재개됐습니다. 2095는 같은 호스트 수정과 iOS 텍스트·PNG 클립보드용 공용 Rust 브리지를 포함했습니다. 2096은 Windows의 현재 연결 세션이 물리 모니터인지 별도 바탕 화면인지 원격 메뉴에 표시합니다. 최신 2097은 같은 기능을 다시 패키징해 서명·무결성·Lint 검사를 통과했지만 2094~2097의 실물 Android 호스트 시험은 아직 남아 있습니다. 자세한 통과 범위와 남은 항목은 [시험 문서](PRIVATE_TESTING.md)에 구분합니다.

## 실제 기기 간 검증 절차

별도 테스트 문서와 사용 중이지 않은 원격 세션에서 실시합니다. 원본 RustDesk와 수정본, 버전, 제어 방향, 키보드 입력 모드, OS 입력 언어를 각각 기록합니다.

1. Mac→Windows: 한국어 IME를 선택한 뒤 전환 버튼과 물리 키 입력으로 `한글 abc 123`을 입력합니다. 작업 표시줄 표시와 실제 문서 내용을 모두 기록합니다.
2. Windows→Mac: 한국어·영어 입력 소스와 Control+Space 설정을 확인하고 같은 문자열을 입력합니다.
3. 자모 조합 중 Backspace, 줄바꿈, 특수문자, 한/영 연속 전환, 한글 뒤 영문 단축키를 확인합니다.
4. 독립 입력창 전송은 실제 원격 문서의 Unicode 문자열과 공백·줄바꿈을 대조합니다.
5. 좌/우/더블 클릭, 드래그는 원본 기능, Ctrl/Cmd+C/V/Z/S를 시험합니다. 전송 권한 해제와 복구, 창 전환·재연결 뒤 눌린 키가 남지 않는지 확인합니다.
6. 연결 안정성은 시간·연결 방식·재연결 횟수를 기록해 별도로 측정합니다. 단기 연결 성공을 안정성 보장으로 표현하지 않습니다.

Android→Windows의 직접 연결·인증 재사용·화면·터치 입력과 Mac→Windows의 직접 연결·인증 재사용·Console 화면·자동 재연결은 통과했습니다. Mac↔Windows 양방향 실제 입력과 IME, Android 호스트 전체 절차, 플랫폼 간 이미지·파일 클립보드와 장시간/다중 클라이언트 부하 시험은 아직 완료하지 않았습니다. 따라서 사용자가 정한 커밋 조건은 아직 충족되지 않았고 커밋하지 않습니다. iPhone은 기기가 없어 미검증으로 남기며 이 조건에서 제외합니다.

Windows 물리 모니터를 조작하려면 세션 선택에서 `Console · 물리 모니터와 같은 화면`을 사용합니다. `RDP · 별도의 Windows 바탕 화면`은 Windows가 따로 만든 세션이라 원격 화면이 변해도 물리 모니터는 그대로일 수 있습니다. RDP와 Console은 같은 바탕 화면을 동시에 비추는 방식이 아니므로, 물리 화면 동기화가 필요한 연결은 RDP를 종료하고 Console로 다시 연결해야 합니다. 최신 후보는 Console과 RDP가 함께 있을 때 저장된 RDP를 자동 선택하지 않고 Console을 기본값으로 표시합니다. Mac v37 설치 뒤 기존 대상과 전송 재연결은 확인했지만 이 선택 창의 실기기 표시는 Mac 잠금 때문에 아직 재검증하지 못했습니다.

새 Windows 호스트 코어는 현재 프로세스가 물리 Console인지 분리된 Windows 세션인지 연결 정보에 포함합니다. 새 Mac·Android 컨트롤러는 원격 메뉴에 `Windows 세션: 물리 모니터` 또는 `Windows 세션: 별도 바탕 화면`을 표시하고, 별도 화면이면 RDP를 종료한 뒤 Console로 다시 연결하라는 설명을 제공합니다. 알 수 없는 구버전 호스트에는 상태를 추정해 표시하지 않습니다. Windows 호스트의 `RDP 별도 바탕 화면 제어`는 기본으로 꺼져 있고, 사용자가 명시적으로 켠 경우에만 별도 세션에 붙습니다. v42 코어 빌드와 단위 시험은 통과했지만 Windows 서비스 배포와 실기기 표시는 아직 미검증입니다.

로컬 테스트 환경에서는 원본 Flutter 워크플로에 지정된 Flutter 3.24.5로 의존성을 해석했습니다. 상위 pubspec.lock에는 추가된 로컬 패키지와 SDK에 맞는 테스트 의존성 변경이 포함됩니다.


## 클립보드 보완 중

Mac·Windows는 기존 텍스트·이미지 동기화와 파일 복사/붙여넣기 경로를 사용한다. macOS 빌드 스크립트는 파일 클립보드 기능을 항상 포함하며, 호스트의 파일 전송 허용과 세션의 파일 복사/붙여넣기 옵션은 별도로 적용한다. Windows 전용 Excel 형식을 macOS의 잘못된 UTI로 읽던 호출을 제외하고, 압축하지 않은 특수 형식에서 실제 데이터 대신 형식 이름이 전달되는 결함을 수정했다.

Android에는 PNG·RGBA 수신과 로컬 이미지 URI 송신을 추가했다. 수신 이미지는 앱의 전용 캐시 안에서만 제공하고, PNG는 원본 바이트를 유지한다. 이미지 참조는 Android의 FileProvider와 클립보드 URI 권한을 사용한다. Android의 포커스 제한과 받는 앱의 MIME 지원이 적용되므로 모든 앱에서 PC와 동일한 자동 붙여넣기를 보장하지 않는다. 현재 일반 파일·다중 항목은 시스템 클립보드로 전송하지 않는다. 원격 제어 메뉴의 ‘파일 전송’에서 로컬/원격 파일을 선택하고 반대쪽 폴더에 붙여넣는 경로를 사용한다. [Android 공식 클립보드 설명](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste)을 따른다.

이 변경의 플랫폼 간 양방향 실제 복사·붙여넣기는 아직 전체 검증을 마치지 않았다. Android 가상 기기에서의 확인과 실물 휴대폰 확인을 구분한다. iPhone 컨트롤러에는 텍스트와 PNG의 양방향 프로토콜·Flutter 브리지·네이티브 pasteboard 경로를 구현했다. iOS의 붙여넣기 개인정보 동작을 피하기 위해 로컬 클립보드 송신은 사용자가 툴바에서 명시적으로 누를 때만 읽으며, 원격에서 받은 항목은 iCloud 범용 클립보드로 전파하지 않는 로컬 항목으로 기록한다. PNG는 크기·서명·IHDR·픽셀 수를 확인한 뒤 디코딩하고 Rust 측 압축 해제 크기도 제한한다. 파일은 iOS 샌드박스 제약 때문에 시스템 클립보드 대신 앱의 파일 전송 화면을 사용한다. 전체 Xcode 빌드와 iPhone/iPad 실기기 시험은 미검증이다.


## 통합 연결 준비

홈의 ‘직접 연결 준비’에서 ‘이 기기 연결 준비’를 누르면 기존 인증서를 재사용하거나 자동 생성하고 직접 수신 서비스를 준비한다. Mac 화면 기록·손쉬운 사용·입력 모니터링, Android 화면 공유·입력 권한 상태를 같은 화면에 표시한다. 승인 필요 항목의 버튼은 OS 권한 요청 또는 설정 화면으로 연결하며, OS가 요구하는 최종 승인은 사용자가 수행한다. 준비 창을 닫아도 서비스는 유지되며 ‘연결 받기 중지’로 종료할 수 있다.

연결 코드는 선택한 주소와 공개 인증서만 포함한다. 비밀번호·개인키는 넣지 않는다. 조작할 기기에서 코드 하나를 붙여넣으면 주소와 인증서를 자동으로 채워 확인 화면을 연다. 사용자가 호스트 지문을 확인하고 ‘확인하고 연결’을 눌러야 등록을 저장하고 실제 연결한다. 기존 인증서를 바꾸는 경우 이전 지문도 표시한다. 비밀번호 또는 호스트 수락은 기존 접속 승인 규칙을 그대로 적용한다.

‘직접 연결 수신’의 성공은 TLS와 등록한 인증서가 일치한 결과다. 방화벽·공유기·회사망 제한은 별도 확인 대상으로 표시하고 OS 방화벽 설정 화면을 제공한다. 앱이 방화벽 전체를 끄거나 공유기 포트를 자동 개방하지 않는다. 시험한 Windows에서는 기존 방화벽·네트워크 상태로 직접 포트에 도달했고 별도 영구 규칙을 추가하지 않았다. 코어 전달에만 사용한 제한적 임시 규칙은 종료 후 0개임을 확인했다.

2026-09-15 로컬 입력·연결 UI 패키지 시험 53개와 상위 앱 집중 시험 24개, Rust iOS 클립보드 시험 6개가 통과했습니다. 이전 Android OS 클립보드 계측 8개도 통과했습니다. 자동 시험 결과와 실제 기기 간 연결·IME·클립보드 결과는 구분합니다.

방화벽은 정상 연결의 선행 조건으로 점검하거나 변경하지 않는다. 연결이 실패할 때만 사용자가 ‘연결이 안 될 때’를 펼쳐 설정 안내를 확인한다. 최신 macOS에서는 네트워크 설정에서 방화벽 항목을 선택하며, 설정 링크를 열었다는 사실만으로 방화벽 통과를 인정하지 않는다.

## HdobbyDesk 이름과 기존 앱 공존

앱 표시 이름은 HdobbyDesk, Android·macOS·iOS 앱 식별자는 `com.hdobby.hdobbydesk`입니다. 네이티브 설정 이름도 HdobbyDesk로 분리하며 기존 RustDesk 설정을 자동으로 가져오지 않습니다. 기존 설치를 제거하거나 덮어쓰지 않습니다. 이전 설정의 공개 서버·비밀번호·개인키를 새 앱에 자동 복사하지 않습니다.

기존 홈페이지·가격·다운로드 안내는 제거하고 원작 출처와 AGPL 전문은 로컬 오픈소스 고지에 보존합니다. 사용하지 않던 iOS Firebase 설정 파일과 그 안의 공개 프로젝트 주소도 제거했습니다. 재생성한 H 모니터 아이콘과 HdobbyDesk 이름을 사용합니다. Rust/JNI/Flutter 채널 등의 내부 이름은 ABI와 프로토콜 호환에 필요한 경우 유지합니다. 브랜드 변경 빌드와 실물 시험 결과는 별도로 확인해야 합니다.
